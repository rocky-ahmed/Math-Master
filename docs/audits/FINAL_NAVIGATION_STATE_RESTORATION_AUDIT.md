## 1. Executive Summary & Architectural Root Cause Analysis

While **`BUG-36`** resolved scroll state loss on `Screen.Home` by introducing `HomeScrollPosition` in `MathViewModel.kt` and wrapping `MainAppContent`'s `when (currentScreen)` switch in `saveableStateHolder.SaveableStateProvider(key = currentScreen.route)`, a full source-level audit of all 19 Compose screen files (`28` active `Screen` destinations and `72+` scrollable containers) uncovered four shared architectural root causes responsible for scroll and browsing context loss inside modules and nested subsections:

1. **Root Cause 1 — Unmanaged Scroll State Creation (`BUG-37`)**:
   - Every non-Home screen either omitted the `state = ...` parameter on `LazyColumn` / `LazyRow` / `LazyVerticalGrid` (causing Compose to allocate an anonymous `rememberLazyListState()` / `rememberLazyGridState()`) or called plain `rememberScrollState()` without ViewModel-backed state ownership or `rememberSaveable` keys scoped to the active route, tab, and item argument.
2. **Root Cause 2 — Transient Local `remember` Ownership for Internal Module Tabs & Filters (`BUG-38`)**:
   - Multi-tab and filter-driven screens (`BcsPreparationScreen`, `NumberSystemScreen`, `QuizzesScreen`, `VisualExplorerScreen`, `ProblemSolverScreen`, `CustomizeScreen`, `BookChapterOverviewScreen`, `BookRevisionScreen`, `TablesScreen`, `PrimesScreen`, `SquaresCubesScreen`, `FormulasScreen`, `FormulaLibraryScreen`, `DashboardScreen`, `BookmarksScreen`) stored `selectedTab`, filter chips, search queries, and expanded card sets in plain `remember { mutableStateOf(...) }`. Whenever a screen left composition to open a child destination, its internal tab and filter state reset on disposal, causing the wrong tab or an unfiltered list to render at `(0, 0)` upon Back return.
3. **Root Cause 3 — Non-Parameterized `SaveableStateProvider` Keys & Shared ViewModel Argument Flows (`BUG-37`)**:
   - `MainAppContent` previously keyed `SaveableStateProvider` by static `currentScreen.route` (e.g., `"book_detail"`, `"book_chapter_overview"`, `"table_detail"`) and `MathViewModel` held single mutable argument flows (`_selectedBookId`, `_selectedBookChapterNumber`, `_selectedBookLessonId`, `_selectedBookPrintedPage`, `_selectedTableNumber`, `_selectedFormulaId`) without snapshotting parent arguments on `navigateTo()`.
4. **Root Cause 4 — Aggressive `SaveableStateHolder` Eviction on Bottom-Navigation Tab Switch (`BUG-39`)**:
   - `MainAppContent`'s `DisposableEffect(activeRoutes)` previously preserved only `Screen.Home.route` when `navigateToTab()` replaced the stack with `listOf(Screen.Home, tabScreen)`, evicting `SaveableStateHolder` entries for the other four bottom-navigation tabs (`Tables`, `Dashboard`, `Bookmarks`, `Quizzes`) whenever the user switched tabs.

## 2. Unified Application-Wide State Preservation Architecture

### 2.1 Reusable Managed State Hooks (`NavigationStateRestoration.kt`)
Created `app/src/main/java/com/example/ui/NavigationStateRestoration.kt` providing four synchronous first-frame restoration primitives:
- **`rememberManagedLazyListState(viewModel, stateKey)`**:
  - Reads the authoritative `ScrollPositionState(firstVisibleItemIndex, firstVisibleItemScrollOffset)` from `MathViewModel.getScrollPosition(stateKey)` before the first composition frame.
  - Initializes `LazyListState` via `rememberSaveable(stateKey, initial.firstVisibleItemIndex, initial.firstVisibleItemScrollOffset, saver = LazyListState.Saver)` so the exact visible item and pixel offset are restored on the very first layout pass without post-composition `scrollToItem()` jumps or flicker.
  - Continuously mirrors `firstVisibleItemIndex` and `firstVisibleItemScrollOffset` via `snapshotFlow` and flushes final coordinates in `DisposableEffect(stateKey) { onDispose { ... } }`.
- **`rememberManagedLazyGridState(viewModel, stateKey)`**:
  - Identical lifecycle and `LazyGridState.Saver` synchronization for `LazyVerticalGrid` containers (`HomeScreen`, `TablesScreen`, `PrimesScreen`).
- **`rememberManagedScrollState(viewModel, stateKey)`**:
  - Synchronous pixel-offset restoration (`ScrollState.Saver` + `viewModel.getScrollPosition(stateKey)`) for `verticalScroll` and `horizontalScroll` filter/tab strips.
- **`rememberManagedUiState<T>(viewModel, stateKey, defaultValue)`**:
  - Reactive `MutableState<T>` backed by `MathViewModel`'s bounded in-memory UI context store (`getUiContextState` / `updateUiContextState`), preserving active sub-tabs, filter chips, search queries, and expanded item IDs across composition disposal.

### 2.2 ViewModel State Coordinator & Argument Snapshot Stack (`MathViewModel.kt`)
- **Bounded LRU State Registries**:
  - `_scrollPositions: MutableStateFlow<Map<String, ScrollPositionState>>` (bounded to `300` entries; synchronized with `homeScrollPosition` when `stateKey == "home:grid"` so all `BUG-36` contracts remain 100% intact).
  - `_uiContextStates: LinkedHashMap<String, Any?>` (bounded to `500` entries).
- **Parameterized Destination State Keys (`getDestinationStateKey(screen)`)**:
  - Computes argument-scoped keys for parameterized destinations (`"table_detail:17"`, `"formula_detail:alg_1"`, `"book_detail:class_8"`, `"book_chapter_overview:class_8:4"`, `"book_lesson:class_8:4:c8_ch4_l1"`, `"book_pdf_reader:class_8:52"`, `"book_interactive_lab:class_8:4:PYTHAGORAS_THEOREM_VISUALIZER"`, `"bcs_preparation:PRELIM_50"`).
- **Parent-Child Argument Snapshot Stack (`_navigationContextStack`)**:
  - Captures `NavigationContextSnapshot` (active `BookId`, `chapterNumber`, `lessonId`, `printedPage`, `labType`, `tableNumber`, `formulaId`, and `BcsExamProfile`) prior to pushing a child destination and restores the parent's exact argument state upon `navigateBack()`.

### 2.3 Persistent Bottom-Navigation Tabs & Argument-Scoped `SaveableStateProvider` (`MainActivity.kt`)
- Wrapped the active destination in `saveableStateHolder.SaveableStateProvider(key = currentDestinationKey)` where `currentDestinationKey = viewModel.getDestinationStateKey(currentScreen)`.
- Updated `DisposableEffect(activeKeys)` to always retain all 5 core Bottom-Navigation tab keys (`Home`, `Tables`, `Dashboard`, `Bookmarks`, `Quizzes`) alongside all keys currently on the backstack (`BUG-39`).
